# Widgetario 26.06 Upgrade — Design

**Date:** 2026-06-02
**Status:** Draft, pending user review
**Owner:** Elton Stoneman

## Goal

Upgrade every in-scope component of the Widgetario sample app to its current LTS (or latest stable, where no LTS exists), confirm the stack still builds and runs, and tag the result `:26.06`.

## In Scope

`src/` only:
- `db` (PostgreSQL)
- `products-api` — `java` and `dotnet` variants
- `stock-api` — `golang` and `dotnet` variants
- `web` — `dotnet` and `dotnet-serilog` variants
- `Widgetario.DotNet.sln` retargets to `net10.0`

## Out of Scope

- `infrastructure/` (Elasticsearch 7.10, Kibana 7.10, Jenkins, Gogs stay on current versions)
- Re-enabling the disabled workflow under `.github/workflows-removed/`
- Application-code refactoring beyond what compilers / runtimes force
- Adding tests, linters, or pre-commit hooks
- Schema or data-model changes in `products-db`
- Multi-arch *publishing* — build files are created, but no ARM64 cross-build is executed locally

## Target Versions (June 2026)

| Component | From | To | Notes |
|---|---|---|---|
| Java (products-api/java) | Spring Boot 2.4.3 / Java 11 | **Spring Boot 4.0.x, Java 25 LTS** | Two-major-version SB jump (2 → 4): javax→jakarta + Spring Framework 6→7 changes |
| .NET (all variants) | .NET 5 / 6 | **.NET 10 LTS** | LTS released Nov 2025; supported through Nov 2028 |
| Go (stock-api/golang) | 1.15 | **1.26** | Latest stable; Go has no LTS |
| PostgreSQL (products-db) | (current Dockerfile base) | **18** | Latest stable major (18.4) |

**Base images:**
- `mcr.microsoft.com/dotnet/aspnet:10.0` (runtime) + `sdk:10.0` (build) — prefer chiseled / distroless `10.0` variants for runtime where available
- `eclipse-temurin:25-jre` (runtime) + `eclipse-temurin:25-jdk` (build)
- `golang:1.26-alpine`
- `postgres:18-alpine`

## Application-Code Policy

Minimum-to-compile-and-run. Specifically:
- **Java:** `javax.*` → `jakarta.*` (Spring Boot 3+ requirement, still applies in 4). Spring Framework 6 → 7 API changes triggered by the SB 4 jump. Renamed `application.properties` keys across 3.x. No idiomatic refactors.
- **.NET:** Bump `<TargetFramework>` to `net10.0`. Update NuGet packages to .NET 10-compatible majors. Fix any compiler-flagged deprecated API calls. No Minimal API rewrites.
- **Go:** Bump `go.mod` to `go 1.26`. `go mod tidy`. Fix anything `go vet ./...` flags.

## Image Tags

Each service has one default-variant `:26.06`; alternate variants are `:<variant>-26.06`. Mirrors the existing `:21.03-v2` pattern.

| Service | Default `:26.06` | Alternate variant |
|---|---|---|
| `widgetario/products-db` | postgres 18 | — |
| `widgetario/products-api` | java | `:dotnet-26.06` |
| `widgetario/stock-api` | golang | `:dotnet-26.06` |
| `widgetario/web` | dotnet | `:dotnet-serilog-26.06` |

## Compose-File Changes

Inside `src/`:

1. **`docker-compose.yml`** — bump every `image:` to the new `:26.06` / `:<variant>-26.06` tag. Service set, ports, env vars unchanged.
2. **`docker-compose-build.yml`** — same tag bumps; build contexts (Dockerfile paths) unchanged.
3. **`docker-compose-dotnet.yml`** — bump tags to `:26.06` (db), `:dotnet-26.06` (products-api, stock-api), `:dotnet-serilog-26.06` (web).

**New build files** mirroring the 21.03 layout (existing `build-21.03*.yml` files left in place for history):
- `src/build-26.06.yml` — common build args (`BUILD_TAG=26.06`, target platforms)
- `src/build-26.06-amd64.yml` — amd64-specific overrides
- `src/build-26.06-arm64.yml` — arm64-specific overrides

The disabled CI workflow already references `21.03` paths and is not edited.

## Build-Validation Strategy

Three gates per service, both for the default stack and the all-dotnet variant.

**Gate 1 — Build.** From `src/`:
```
docker compose -f docker-compose-build.yml build <service>
```
Must complete with no warnings about deprecated base images or unresolved dependencies.

**Gate 2 — Up.** After all services in the stack are built:
```
docker compose -f docker-compose-build.yml up -d
docker compose ps
```
All containers `running`, none `restarting`/`exited`. Wait ~20s for Spring Boot startup.

**Gate 3 — Curl health:**
- `web` → `curl -fsS http://localhost:8080/` → 200, non-empty HTML
- `products-api` → `curl -fsS http://localhost:8081/products` → JSON array
- `stock-api` → `curl -fsS http://localhost:8082/stock` → JSON (verify both golang `:8080` internal and dotnet `:80` internal map to 8082 external)

A service is "upgraded" only when all three gates pass. After the default stack passes, tear down (`docker compose down`) and repeat all three gates with `docker-compose-dotnet.yml` for the all-dotnet variant.

No new tests added. No CI re-enabled. Validation is local-only and manual.

## Execution Sequence

Each step is one commit, ending in a verified-green state.

1. **`db`** — `postgres:18-alpine` base. Verify products-db starts and accepts connections (`pg_isready`).
2. **`products-api/java`** — Java 25 + Spring Boot 4.0.x. javax→jakarta, property renames, Dockerfile base swap. Build → up → curl `/products`.
3. **`products-api/dotnet`** — .NET 10. `<TargetFramework>net10.0</TargetFramework>`, NuGet bumps, Dockerfile base swap. Build → up → curl `/products`.
4. **`stock-api/golang`** — Go 1.26. `go.mod` bump, `go mod tidy`, Dockerfile base swap. Build → up → curl `/stock`.
5. **`stock-api/dotnet`** — .NET 10. Same pattern as step 3.
6. **`web/dotnet`** — .NET 10. Default web variant. Build → up → curl `/`.
7. **`web/dotnet-serilog`** — .NET 10 + Serilog package bumps. Build → up → curl `/`.
8. **Wire-up commit** — bump all `image:` tags in `docker-compose.yml`, `docker-compose-build.yml`, `docker-compose-dotnet.yml`. Add `build-26.06.yml`, `build-26.06-amd64.yml`, `build-26.06-arm64.yml` mirroring 21.03 layout. Update `Widgetario.DotNet.sln` if any project paths changed.
9. **Full-stack validation** — default stack: build all → up → curl all three endpoints. Then dotnet stack: build all → up → curl all three. Both must pass before this commit.

**Commit message style:** match existing repo (short imperative, no Conventional Commits prefix — recent commits read `Add Elasticsearch & Kibana`, `Bump to .NET 5 & add ARM64 support`).

**Rollback boundary:** any single step failure stops the sequence. Fix in place or revert that commit; do not advance with a red service.

## Risks & Open Questions

- **Spring Boot 2 → 4** is a two-major jump (no intermediate SB 3 stop). Expect more breaking changes than the typical single-major bump. If breakage exceeds "minimum to compile" bounds, surface to user before sinking time into rewrites.
- **`.NET 5/6` Solution** may have project-format quirks that need `dotnet sln` re-add when retargeting. The retargeting commit should rebuild from a clean `obj/` and `bin/`.
- **stock-api dotnet** uses internal port `:80` vs golang `:8080`. Either keep the port mapping intact in compose (8082 external, internal differs by variant) or align internal ports to 8080. Default plan: keep as-is to minimise blast radius.
- **No tests** means "it builds and curls a 200" is the only correctness signal. Logic regressions will not be caught. User has accepted this.
