# Widgetario 26.06 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade every in-scope component of the Widgetario sample app to current LTS (or latest stable), verify each service builds + runs + responds to health checks, and tag the result `:26.06`.

**Architecture:** Service-by-service upgrade. Each service produces one self-contained green commit (SDK bump → dependency bump → Dockerfile bump → `docker compose build` → `up` → curl). After all seven services are green, one wire-up commit retags every `image:` to `:26.06` and adds release-style build files. A final commit validates the full default stack and the all-dotnet stack.

**Tech Stack:**
- PostgreSQL 18 (alpine)
- Java 25 LTS, Spring Boot 4.0.x, Maven
- .NET 10 LTS (ASP.NET Core), NuGet
- Go 1.26, Go modules
- Docker / Docker Compose (compose v2 syntax)

**Reference spec:** `docs/superpowers/specs/2026-06-02-widgetario-26.06-upgrade-design.md`

## Cross-Cutting Notes

### .NET ASP.NET Core port

.NET 8+ changed the default listening port from 80 to 8080. Existing compose files map external ports to internal `:80`. Each .NET service Dockerfile must explicitly preserve `:80` by setting:

```dockerfile
ENV ASPNETCORE_HTTP_PORTS=80
```

This is required in `products-api/dotnet`, `stock-api/dotnet`, `web/dotnet` (and `Dockerfile.v2`). Without it, `curl localhost:8081`, `:8082`, `:8080` all fail even though the container is "running."

### Deprecated NuGet packages

The existing .NET projects reference `Jaeger` and `OpenTracing*` packages. These have not been updated since ~2020 and may not have `net10.0`-compatible releases. **Policy when restore fails:**
1. First try the latest version published — `dotnet add package <name>` resolves the newest compatible.
2. If no `net10.0`-compatible version exists, remove the `<PackageReference>` and delete the related setup code in `Program.cs` / `Startup.cs`. This is the minimum-touch fix.
3. Do NOT replace with OpenTelemetry — that's architectural rework outside the spec's "minimum to compile" policy.

### Spring Boot 4 application.properties

`spring.datasource.platform=postgres` was removed in Spring Boot 2.5 and is gone in 3.x/4.x. Driver is auto-detected from the JDBC URL, so the line is deleted with no replacement.

### Commit message style

Recent repo commits read like `Add Elasticsearch & Kibana`, `Bump to .NET 5 & add ARM64 support`. **No** Conventional Commits prefixes (no `feat:`, `chore:`). Match this style.

### Docker compose CLI

Use `docker compose` (v2 plugin), not `docker-compose` (v1 standalone). All commands in this plan use the v2 form.
